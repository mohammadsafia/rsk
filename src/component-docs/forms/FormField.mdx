## In a form

Every `Form*` field renders through `FormField`, so labels, help text, required marks and errors look and behave the same. Submit the form empty to see the errors.

</Example>

## Anatomy

| Part | data-slot | Notes |
|---|---|---|
| Root | `form-field` | `data-invalid` while the field has an error |
| Label row | `form-field-label` | Label, required `*` and an optional ⓘ tooltip button beside the label (kept out of the field's name) |
| Control | `form-field-control` | Receives `id`, `invalid`, `aria-labelledby`, `aria-describedby`, `aria-required` |
| Message | `form-field-message` | The error (danger) or else the `description` (muted); referenced by `aria-describedby` |

## Building a custom field

Wrap any control in `FormField` and spread the render prop onto it.

```tsx
<FormField id={id} label="Licence number" description="As printed on the card" error={error}>
  {(control) => <Input {...control} {...register('licence')} />}
</FormField>
```

## Accessibility

- The label is a real `<label>` tied to the control; the message line is wired with `aria-describedby`, and errors set `aria-invalid`.
- The ⓘ tooltip button sits outside the label, so it is not read as part of the field's name.

## RTL notes

- The label, required mark and tooltip button follow the reading direction; the message line aligns to the start.
