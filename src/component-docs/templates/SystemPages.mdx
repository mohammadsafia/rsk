Four pages for when the app can't show what was asked for. Each has the logo (or sits in the app shell), a status code, a plain explanation and a way back home, in English and Arabic. The examples below use `layout="preview"` to sit inside this page; as routes they fill the screen.

## Not found (404)

The catch-all route: any address that matches no page.

<Example title="404" code={`<NotFoundPage />`}>
  <NotFoundPage layout="preview" />
</Example>

## Server error (500)

`ServerErrorPage` is the error page of the whole router: a page that throws while rendering, or a loader that fails. It takes `{ error, retry, retrying, notFound }` (`ErrorScreenProps`) and never reads the router itself: in a Vite app the block index's `BlockErrorElement` fills them from React Router (**Try again** re-runs the route's loaders; a loader that throws a 404 response shows the not-found page), in a Next app `error.tsx` maps its `{ error, reset }` onto them. This preview shows `ServerErrorScreen`, the same page without the error wiring, which you can use anywhere else.

<Example title="500" code={`<ServerErrorScreen onRetry={() => window.location.reload()} />`}>
  <ServerErrorScreen layout="preview" onRetry={() => {}} />
</Example>

## Add it

```bash
pnpm kit:add system-pages
```

The pages land in `src/blocks/system-pages/` and join the router through `src/blocks/index.ts` — no router edits:

<PropsTable
  rows={[
    { prop: '*', type: 'NotFoundPage', description: 'Placed before the app’s own catch-all, so it replaces it.' },
    { prop: '/maintenance', type: 'MaintenancePage', description: 'A page of its own, without the app shell.' },
    { prop: '/no-access', type: 'NoAccessPage', description: 'Inside the app shell, behind sign-in.' },
    { prop: 'errorElement', type: 'ServerErrorPage', description: 'The error page of the app’s routes.' },
  ]}
/>

`pnpm kit:remove system-pages` puts the app's own 404 and error page back.

`SystemPage` (also exported) is the shared layout — `code` or `icon`, `title`, `description`, `kind` and extra actions as children — for a system page of your own.

## Accessibility

- Each page's title is its `h1` and the page is the `main` landmark (the shell provides it for the no-access page). The server error is announced as an alert.
- The status code is drawn large but read once, before the title.

## RTL notes

- Everything is centred; the home and retry icons don't point anywhere, so nothing mirrors.
