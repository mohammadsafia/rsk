# Public Docs Site — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A standalone `/docs` site that reads like a professional UI kit:
- a docs shell (top bar, grouped left nav, mobile drawer),
- reference pages with `<Example>` Preview · Code frames whose code is captured at build time,
- consistent `<PropsTable>`s,
- an "On this page" outline and prev/next links,
- ⌘K search,
- a card-grid overview,
- six guides.

**Architecture:**
- **Build time:** a remark plugin (`scripts/docs/remark-docs.ts`), registered in the MDX config, does three things:
  - injects each `<Example>`'s children source as a `code` prop,
  - gives `h2`/`h3` headings stable ids,
  - exports `headings` for search.
- **Runtime:** the docs live under a public `DocsLayout` route outside `AuthGuard`/`AppLayout`. Pages read the existing MDX registry. MDX building blocks are provided globally through `mdxComponents`, so pages don't import them.

**Tech Stack:** React 18, react-router 6, MDX 3 (`@mdx-js/rollup`, remark plugins), the kit's Tabs/Command/Table/Alert, nuqs (overview filter), Vite+ (`vp`), happy-dom + @testing-library/react, playwright-cli.

**Spec:** `docs/superpowers/specs/2026-10-16-docs-site-design.md`. Mockups: `.superpowers/brainstorm/96153-1792163351/content/{docs-layout,components-index}.html` (choices A and A).

### Plan decisions not spelled out in the spec (keep them)

- **One remark plugin, three jobs** (`remark-docs.ts`): Example source, heading ids, and `export const headings`. One tree walk, and it's testable on a hand-built tree.
  - **Slug rule:** lower-case; spaces → `-`; drop anything outside `[a-z0-9-]`; de-duplicate with `-2`, `-3`.
- **MDX building blocks are global.** `Example`, `PropsTable`, `Callout` and `DoDont` are registered in `mdxComponents` (`component-docs/gallery/utils.tsx`), so MDX pages use them without imports. Every docs page renders through `MDXProvider components={mdxComponents}`.
- **Guides** live in `src/component-docs/guides/*.mdx` with `category: Guides` and a new optional frontmatter field `order: number`. The left nav's "Getting started" group comes from category `GUIDES` sorted by `order`. `introduction` renders at `/docs`.
- **Import line** on component pages:
  - The component is `title`.
  - The path comes from the category: UI → `@components/ui`, Forms → `@components/forms`, Shared → `@components/shared`, Tables → `@components/tables`, Calendar → `@components/calendar`, Hooks → `@hooks/shared`.
  - Frontmatter `importFrom` overrides it.
  - There is no import line for Guides or Foundations.
- **Thumbnails** are a hand-made map for the docs that matter most (at least 16). The rest get a category glyph. The map is `aria-hidden` and `inert`.
- **The registry excludes underscore folders** (`/_template/`, `/_fixtures/`), so test fixtures and templates never appear as docs.

## Review Focus

1. **Captured code is exactly what renders.** Expressions (`{value}`), nested elements, multi-line props and helper-component examples (`code` override) must all show correct, dedented code. → Task 1 tests each case on a real fixture MDX.
2. **Example toggles stay scoped.** Flipping RTL/dark inside one example must not change `<html dir>`/theme or other examples, and the toggle state resets on navigation. → Task 2 asserts `document.documentElement` is untouched.
3. **Public, deep-linkable routes.** `/docs/components/button#variants` loads without auth and scrolls to the heading. Old `/components/<id>` links redirect. Unknown ids show the docs not-found page. → Task 3 tests all three.
4. **Search keyboard flow in Arabic.** ⌘K opens it, focus is in the input, arrows plus Enter navigate, section results land on the anchor, and Arabic diacritics are ignored. → Task 5 tests each step.
5. **Migration is complete and enforced.** No MDX page keeps a duplicated "Code" block next to an `<Example>`, every example has a title, and every component page ends with API, Accessibility and RTL notes. → Task 9's `docs:lint` rules fail the build otherwise. Tasks 7–8 make the pages pass.

- [ ] **Step 3: Implement `scripts/docs/remark-docs.ts`**

```ts
/**
 * remark-docs — one pass over each docs MDX file:
 * 1. <Example> without `code` gets the dedented source of its children as `code` (Preview · Code always match).
 * 2. h2/h3 headings get stable slug ids (outline, anchors, search).
 * 3. `export const headings = [...]` for the docs search index.
 */
type Position = { start: { offset?: number }; end: { offset?: number } };
type Node = { type: string; name?: string; depth?: number; value?: string; children?: Node[]; attributes?: Attr[]; position?: Position; data?: Record<string, unknown> };
type Attr = { type: 'mdxJsxAttribute'; name: string; value: unknown };
type File = { value: unknown };

export const slugify = (text: string, seen: Map<string, number>): string => {
  const base =
    text
      .normalize('NFKD')
      .toLowerCase()
      .replace(/[^a-z0-9\s-]/g, '')
      .trim()
      .replace(/\s+/g, '-')
      .replace(/-+/g, '-') || 'section';
  const count = seen.get(base) ?? 0;
  seen.set(base, count + 1);
  return count === 0 ? base : `${base}-${count + 1}`;
};

const textOf = (node: Node): string => (node.type === 'text' || node.type === 'inlineCode' ? (node.value ?? '') : (node.children ?? []).map(textOf).join(''));

const dedent = (source: string): string => {
  const lines = source.replace(/^\n+|\s+$/g, '').split('\n');
  const indents = lines.slice(1).filter((line) => line.trim()).map((line) => line.match(/^ */)![0].length);
  const cut = indents.length > 0 ? Math.min(...indents) : 0;
  // The first line starts at the child's own offset, so it carries no indentation.
  return [lines[0], ...lines.slice(1).map((line) => line.slice(Math.min(cut, line.match(/^ */)![0].length)))].join('\n');
};

const walk = (node: Node, visit: (node: Node) => void) => {
  visit(node);
  node.children?.forEach((child) => walk(child, visit));
};

const literal = (value: unknown): unknown => {
  if (Array.isArray(value)) return { type: 'ArrayExpression', elements: value.map(literal) };
  if (value && typeof value === 'object') {
    return {
      type: 'ObjectExpression',
      properties: Object.entries(value).map(([key, inner]) => ({
        type: 'Property',
        kind: 'init',
        method: false,
        shorthand: false,
        computed: false,
        key: { type: 'Identifier', name: key },
        value: literal(inner),
      })),
    };
  }
  return { type: 'Literal', value };
};

export default function remarkDocs() {
  return (tree: Node, file: File) => {
    const source = String(file.value ?? '');
    const seen = new Map<string, number>();
    const headings: Array<{ depth: number; text: string; slug: string }> = [];

    walk(tree, (node) => {
      if (node.type === 'mdxJsxFlowElement' && node.name === 'Example' && !node.attributes?.some((attr) => attr.name === 'code')) {
        const children = node.children ?? [];
        const start = children[0]?.position?.start.offset;
        const end = children.at(-1)?.position?.end.offset;
        if (start !== undefined && end !== undefined) {
          (node.attributes ??= []).push({ type: 'mdxJsxAttribute', name: 'code', value: dedent(source.slice(start, end)) });
        }
      }

      if (node.type === 'heading' && (node.depth === 2 || node.depth === 3)) {
        const text = textOf(node).trim();
        const slug = slugify(text, seen);
        node.data = { ...node.data, hProperties: { ...((node.data?.hProperties as object) ?? {}), id: slug } };
        headings.push({ depth: node.depth, text, slug });
      }
    });

    const value = `export const headings = ${JSON.stringify(headings)}`;
    tree.children?.push({
      type: 'mdxjsEsm',
      value,
      data: {
        estree: {
          type: 'Program',
          sourceType: 'module',
          body: [
            {
              type: 'ExportNamedDeclaration',
              specifiers: [],
              source: null,
              declaration: {
                type: 'VariableDeclaration',
                kind: 'const',
                declarations: [{ type: 'VariableDeclarator', id: { type: 'Identifier', name: 'headings' }, init: literal(headings) }],
              },
            },
          ],
        },
      },
    });
  };
}
```

**`dedent` check:** the first child's `start.offset` points at `<`, so line 0 has no indentation. Later lines are cut by the smallest common indentation. The unit test fixes the expected output: two-space-indented children become flush, and the inner props keep their relative two spaces. If the expected string differs because of how this splits lines, fix the implementation, not the test. The test states the contract.

**Wire it:** in `vite.config.ts`, `import remarkDocs from './scripts/docs/remark-docs';` and append `remarkDocs` to `remarkPlugins`, after `remarkGfm`. Make sure `tsconfig.scripts.json` covers `scripts/docs/**`; extend its `include` if it doesn't.

```ts
import { type ComponentDocEntry, normalizeCategoryKey } from '@component-docs/registry';

const ORDER = ['GUIDES', 'FOUNDATIONS', 'UI', 'FORMS', 'SHARED', 'TABLES', 'CALENDAR', 'HOOKS'] as const;
const LABEL_KEY: Record<(typeof ORDER)[number], string> = {
  GUIDES: 'guides',
  FOUNDATIONS: 'foundations',
  UI: 'ui',
  FORMS: 'forms',
  SHARED: 'shared',
  TABLES: 'tables',
  CALENDAR: 'calendar',
  HOOKS: 'hooks',
};

export const docHref = (entry: Pick<ComponentDocEntry, 'id' | 'category'>) => {
  const category = normalizeCategoryKey(entry.category);
  if (entry.id === 'introduction') return '/docs';
  if (category === 'GUIDES' || category === 'FOUNDATIONS') return `/docs/${entry.id}`;
  return `/docs/components/${entry.id}`;
};

export const docsNavGroups = (entries: ReadonlyArray<ComponentDocEntry>) =>
  ORDER.map((key) => ({
    key,
    labelKey: `nav.groups.${LABEL_KEY[key]}`,
    items: entries
      .filter((entry) => normalizeCategoryKey(entry.category) === key)
      .sort((a, b) => (key === 'GUIDES' ? (a.order ?? 99) - (b.order ?? 99) : a.title.localeCompare(b.title)))
      .map((entry) => ({ id: entry.id, title: entry.title, href: docHref(entry) })),
  })).filter((group) => group.items.length > 0);

/** Flat reading order for prev/next. */
export const docsReadingOrder = (entries: ReadonlyArray<ComponentDocEntry>) => docsNavGroups(entries).flatMap((group) => group.items);
```

```tsx
  const { t } = useAppTranslation('docs');
  const [active, setActive] = useState(headings[0]?.slug);

  useEffect(() => {
    if (typeof IntersectionObserver === 'undefined') return;
    const targets = headings.map((heading) => document.getElementById(heading.slug)).filter((node): node is HTMLElement => !!node);
    const observer = new IntersectionObserver(
      (entries) => {

        if (visible) setActive(visible.target.id);
      },

    targets.forEach((target) => observer.observe(target));
    return () => observer.disconnect();

              aria-current={active === heading.slug ? 'location' : undefined}
```

```ts
import { type ComponentDocEntry, normalizeCategoryKey } from '@component-docs/registry';
import { docHref } from '@layouts/docs-layout/docs-nav';

const fold = (value: string) =>
  value
    .normalize('NFD')
    .replace(/[̀-ًͯ-ٰٟ]/g, '')
    .toLowerCase();

export type SearchItem = { id: string; group: 'guides' | 'components' | 'sections'; title: string; subtitle?: string; href: string; keywords: string };

export const buildSearchIndex = (entries: ReadonlyArray<ComponentDocEntry>): SearchItem[] =>
  entries.flatMap((entry) => {
    const isGuide = ['GUIDES', 'FOUNDATIONS'].includes(normalizeCategoryKey(entry.category));
    const href = docHref(entry);
    const page: SearchItem = {
      id: entry.id,
      group: isGuide ? 'guides' : 'components',
      title: entry.title,
      subtitle: entry.description,
      href,
      keywords: fold([entry.title, entry.description, entry.category, ...(entry.tags ?? [])].join(' ')),
    };
    const sections = (entry.headings ?? []).map<SearchItem>((heading) => ({
      id: `${entry.id}#${heading.slug}`,
      group: 'sections',
      title: heading.text,
      subtitle: entry.title,
      href: `${href}#${heading.slug}`,
      keywords: fold(`${heading.text} ${entry.title}`),
    }));
    return [page, ...sections];
  });
```
